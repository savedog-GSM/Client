# 카카오 도보 길찾기

해커톤 경로 화면은 길찾기 종류 선택 없이 도보 경로를 표시합니다. 지도 범례는 **로보독 예상 이동 경로**이며 거리·시간·이동 안내를 함께 보여줍니다. 실제 조회는 카카오 도보 API를 사용하고 로보독 수집 기록이나 관제 토큰이 없어도 요청할 수 있습니다.

## Vercel 설정

1. 카카오 개발자 콘솔에서 현재 앱의 **REST API 키**를 확인합니다. 지도 JavaScript 키와 다릅니다.
2. Vercel 프로젝트의 Environment Variables에 `KAKAO_REST_API_KEY`로 등록합니다. Preview와 Production 중 실제 사용하는 환경을 선택합니다.
3. 변경 코드를 배포합니다. 환경 변수를 추가·변경한 후에는 재배포해야 합니다.
4. `/map`에서 학교와 송정공원역을 선택하고 경로 찾기를 누릅니다.

REST 키에 `VITE_` 접두사를 붙이지 않습니다. 브라우저에는 키를 전달하지 않고 `/api/walking-route` 함수에서만 사용합니다. Spring 서버 코드는 변경하지 않습니다. REST 키의 카카오 API 사용 권한·쿼터·IP 제한도 확인합니다.

## 요청 흐름

브라우저 → 같은 출처의 `/api/walking-route` → 카카오 `GET https://dapi.kakao.com/v2/routing/walk` → 지도 경로 표시

- 요청 좌표는 WGS84이며 카카오에는 X=경도, Y=위도로 전달합니다.
- 탐색 옵션은 `BROAD_FIRST`입니다. 카카오의 넓은 길 우선 경로이며 로보독 센서 위험도를 반영한 안전 경로는 아닙니다.
- 카카오 응답의 구간별 좌표를 순서대로 이어 표시합니다. 실제 경로를 얻지 못하면 직선·샘플 경로로 대체하지 않습니다.
- 키 누락, 인증·권한 오류, 쿼터 제한, 주변 보행 도로 없음, 시간 초과를 화면에 안내합니다.
- 시연 모드는 카카오를 호출하지 않으며 예시 경로·시간임을 표시합니다.
- 로컬 Vite 서버는 Vercel 함수를 실행하지 않습니다. 전체 연결은 Vercel Preview 또는 `vercel dev`에서 확인합니다.

## 확인 범위

함수·화면 테스트에서는 카카오 공식 응답 형식의 fixture를 사용합니다. 실제 학교→송정공원역 조회는 REST 키 등록과 배포 이후 확인해야 합니다.
