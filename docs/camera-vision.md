# 카메라 인식 연결

관제 화면의 **로보독 제어 및 연결 정보 → 카메라 보기**에서 최신 사진과 인식 결과를 함께 조회합니다. 연결 설정에 서버 주소와 관제 토큰을 입력합니다.

- `GET /api/robot/vision`: `Authorization: Bearer <관제 토큰>`
- `GET /api/robot/frames/latest/url`: 기존 사진 조회 API
- 조회를 켜면 두 요청을 병렬로 보내고, 완료 후 1초 뒤 다시 조회합니다. 중지하거나 화면을 나가면 요청을 취소합니다.
- 사진 조회 실패와 인식 결과 조회 실패는 따로 표시합니다.
- 모델 비활성, 사진 수신 대기, 오래된 결과를 구분합니다. `fresh: false`이거나 요청 시작 후 3초가 지난 결과에는 현재 위험 점수를 표시하지 않습니다.
- 종합 위험도는 기존 센서·실시간 통신 응답을 그대로 사용합니다. 프론트에서 카메라 점수를 합치거나 추가 정지 명령을 보내지 않습니다.
- 시연 모드의 사진과 인식 결과는 예시입니다.

## 중계 프로그램 담당 작업

중계 프로그램에서 카메라를 한 번 열고 계속 읽으면서 약 1초 간격으로 JPEG를 업로드합니다.

```http
POST https://savedog.https.gsmsv.site/api/robot/frames
Content-Type: image/jpeg
X-Device-Token: <기기 토큰>

<2MB 이하의 JPEG 바이트>
```

JSON이나 multipart가 아닌 JPEG 본문을 보냅니다. 사진 업로드와 함께 기존 `/api/robot/telemetry` 센서 전송도 유지해야 카메라 점수가 서버의 위험도 판단에 반영됩니다. 프론트는 스마트폰 카메라를 켜거나 사진 업로드를 대신하지 않습니다.

## 실제 연결 확인

1. 서버의 인식 모델을 켜고 중계 프로그램에서 사진·센서를 전송합니다.
2. 관제 토큰으로 로그인한 화면에서 카메라 보기를 누릅니다.
3. 사진 수신 시각, 물체 이름, 신뢰도, 분석 시간을 확인합니다.
4. 사진 전송을 멈춘 뒤 결과가 오래된 상태로 바뀌는지 확인합니다.
5. 센서 응답의 위험도·근거와 기존 경고 흐름을 확인합니다.

실제 로봇·관제 토큰을 통한 통합 검증은 별도로 필요합니다. 토큰이 없는 공개 요청은 401로 거부됩니다.
